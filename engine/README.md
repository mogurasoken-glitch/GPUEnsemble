# engine/

独自のパイプライン実行器の置き場です（今は空）。

MVP（フェーズ1）では、推論の実行は llama.cpp の層分割に任せることにしました（2026-11）。llama.cpp の層分割は、
設計どおり「段ごとに連続した層を持ち、段の間で活性値だけを渡す」パイプラインで、配置プランナが決めた割り振りで動かすと、
手で調整した llama.cpp より生成が 36% 速くなりました（[benchmarks/phase1a-e5-llamacpp.md](../benchmarks/phase1a-e5-llamacpp.md)）。
自作しても、同じ ggml のカーネルを使う限り速さは同等が上限です。

ここに実行器を作るのは、llama.cpp では得られない速さの見込みが立ったときです。候補:

- プロンプトをチャンクに分けて段を重ねて流す（llama.cpp はプロンプトの各バッチを段ごとに順に処理する）
- 段の間の受け渡しを pinned RAM で直接行い、待つ間のカードのクロック低下を避ける
- 複数のリクエストを段に重ねて流すマイクロバッチ（フェーズ3）

方針は [docs/DESIGN.md](../docs/DESIGN.md) のまま: 段ごとに1スレッド・1デバイス、ビルドは CMake + MSVC + CUDA Toolkit 12.x。
