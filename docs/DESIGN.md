# GPUEnsemble 設計メモ

正本は設計ドキュメント（Claude Doc）で、ここはリポジトリ内で参照するための要約です。数値は公称値からの概算で、フェーズ0の実測で置き換えます。

## 方針

1. **層分割（パイプライン並列）だけを使う。** テンソル並列は1トークンあたり 100 回以上の同期が必要で、PCIe 経由（特に Windows の GeForce は P2P 不可）では割に合わない。
2. **重みも KV キャッシュも重複させない。** 各カードは自分の担当層だけを持つ。これで VRAM がほぼ単純に足し算になる。
3. **計算カーネルは書かない。** ggml を版固定で取り込み、自作するのは配置プランナとパイプライン実行器。
4. **8GB 級のカードも使う。** Strata は 8GB 以下のカードを既定で外すが、GPUEnsemble は小さいカードにも数層を持たせる。

## 部品

```
[OpenAI 互換 API サーバ]  (server/, Python)
          │ リクエスト
          ▼
[パイプライン実行器]  (engine/, C++)
   段1: GPU0 ─活性値→ 段2: GPU1 ─活性値→ 段3: GPU2（出力ヘッド）
          ▲ 層の割り当て
[デバイス検出] → [配置プランナ]  (planner/, Python)
          │
[土台: ggml カーネル — CUDA 12 / CPU]  (third_party/)
```

- **デバイス検出:** 空き VRAM、実測メモリ帯域、PCIe リンク、使えるバックエンドを調べる。画面出力に使うカードは空き VRAM が減るので、必ず実測値を使う。
- **配置プランナ:** GGUF の層ごとの重みサイズと、文脈長から求めた KV 量を入力に、「全層が入り、各段の読み出し時間の合計が最小」になる連続分割を探す。出力ヘッドを持つ最後の段は、最も速く VRAM の大きいカード（開発機では 2080 Ti）に置く。
- **パイプライン実行器:** 段ごとに専用スレッド。段の間は pinned RAM 経由で活性値だけを渡す（70B 級で 1トークン約 16KB）。プロンプトはチャンクに分けて段を重ねて流す。
- **API とモニタ:** `/v1/chat/completions` を提供。段ごとの処理時間、VRAM、温度を表示し、どのカードが足を引っ張っているかを見せる。

## MVP での実行（2026-11 決定）

MVP では、パイプライン実行器を自作せず、llama.cpp の層分割（`-sm layer -dev ... -ts ...`、MoE エキスパートは `-ot` で RAM へ）に
配置プランナの割り振りを渡して実行する。llama.cpp の層分割はこの設計のパイプラインそのもので、プランナの割り振りで手調整より
生成が 36% 速くなった（benchmarks/phase1a-e5-llamacpp.md）。API は llama-server の OpenAI 互換 API、モニタは planner の `monitor`
（nvidia-smi と llama-server の `/metrics`）。llama.cpp は段ごとの処理時間を出さないので、モニタの段ごとの時間はプランの見積もりを
実測の生成速度に合わせたもの。独自の実行器（engine/）は、llama.cpp では得られない速さの見込みが立ってから作る。

## 速度の考え方

生成は各段が順番に動くので、1トークンの時間は「各カードが担当分の重みを読む時間」の合計になる。カードを足すと載るモデルは大きくなるが、単一リクエストの速度は上がらない。

開発機（2080 Ti 約 616GB/s、2080 SUPER 約 496GB/s ×2、VRAM 合計 27GB）の目安:

| モデル | 重み | 収まるか | 生成速度の理論上限 |
| --- | --- | --- | --- |
| 32B 級の密モデル Q4_K_M | 約 20GB | 収まる | 約 28 トークン/秒 |
| 70B 級の密モデル IQ2_XS | 約 21GB | ぎりぎり | 約 25 トークン/秒 |
| 120B 級 MoE（gpt-oss-120b） | 約 61GB | RAM 64GB と併用で可 | RAM と PCIe の帯域次第 |

実効値は理論上限の 6〜8 割を見込む。

## 開発機の制約

- Xeon E5-2680（v1）は AVX2 を持たないため、CPU 側での量子化計算が遅い。MoE の退避分は CPU で計算するより、PCIe（CPU 直結 40 レーン）で GPU へ流し込んで GPU で計算する方式を主にし、どちらが速いかはプランナが実測で選ぶ。
- Windows（WDDM）では pinned メモリを大きく取りにくい。Strata も複数GPU時は 8GiB までしか pinned にしていない。RAM 退避はこの上限を前提に設計する。
- CUDA 13 は Maxwell / Pascal / Volta 向けにビルドできないため、CUDA 12.x を基準にする。

## MVP でやらないこと

学習やファインチューニング、テンソル並列、独自の量子化形式、独自のパイプライン実行器。（デスクトップアプリと複数PC は、当初は対象外としていたが先に作った）
